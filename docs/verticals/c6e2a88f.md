## The failure

The catalogue-versioning release (19 Oct 2026) renamed the standards catalogue pin on submissions from `standardsVersion` to `catalogueVersion`. Pre-release submissions were back-filled and keep a read-only `standardsVersion` alias; submissions pinned to the newly published catalogue **2026.4** carry `catalogueVersion` only. The decision service still reads `submission.standardsVersion.label`, so **Record decision** on `ARB-2026-0151` (Pharmacy benefits API gateway) fails with a `TypeError`; every other submission records cleanly.

## What happens when it fires

1. Sentry capture + Slack alert in the configured channel.
2. A P2 ServiceNow incident for **Enterprise Architecture Platform Engineering**, CI **Architecture Review Hub**, short description written as an operator would, description = the Devin prompt.
3. The ServiceNow business rule `Devin: dispatch P1/P2 incident` posts the incident to the Devin Automation webhook configured for the group (`x_devin.webhook_url.<group sys_id>`); the Devin session investigates, opens the fix PR and writes findings + PR URL back to the incident as work notes.
4. Humans keep release ownership: Devin never deploys and never closes or resolves the incident.
