DEVIN AUTOMATIONS

Nothing broke. There is still work.

On-call answers the question “what happens when something breaks?” This answers “what happens when nothing breaks — and there is still work an agent can find?” A scheduled patrol reads production telemetry, ranks the real cost, files the work, and fixes the worst one.

Ranked by what it actually costs

The patrol runs unprompted on a schedule. It reads the app's real per-query timing events out of Datadog, groups them by query, and ranks by total time per day rather than single-query duration — a 3 ms query running tens of thousands of times a day outranks a 400 ms query running a few dozen. It dedupes against the existing Linear backlog, files only the top one or two findings, then fixes the worst one in code and opens a PR for review.

Step 01
Measure
Reads real db.query timing events — count, mean, p95, total per day. Never estimates.
Step 02
Dedupe
Checks open Linear issues first, so a known finding is reported, not refiled.
Step 03
File
One or two issues with the measured evidence and the code location — not a wall of tickets.
Step 04
Fix
Fixes the top finding with proven output equivalence and before/after numbers. Opens a PR; never merges.
Step 05
Report
One ranked digest in Slack with the filed issues and the PR. A quiet day is a valid result.

Run the patrol now

The same workflow, on demand. Backtest runs file into a throwaway patrol-backtest-* Linear project so they never touch the production backlog, and a second press inside the attach window reuses the running session instead of starting another.

What a run does
Measures the same trailing window, reports the window it actually measured, files its findings in an isolated project, fixes the top-ranked one, opens a PR without merging, and posts a digest labelled as a backtest.
